ShenSec now runs as a standalone Windows desktop application, with automatic login, session renewal and verified multi-role access comparisons.

### Download and open

- **Single exe:** download `ShenSec-0.5.0b1-windows-x64.exe`, then double-click.
- **Faster daily startup:** download the portable ZIP, extract everything, then open `ShenSec.exe`. Keep `_internal` beside it.
- Windows 10/11 x64. Python, uv, terminal commands and administrator rights are not required.
- This beta is unsigned. Check the official source and `SHA256SUMS.txt` before following your device's unknown-publisher policy.

### Start with the local demo

Click **Try local demo**. The isolated fixture demonstrates four roles, two endpoints, before/after history, three fixed access violations and four session renewals. Closing the demo stops its service and removes temporary history. The main workspace is preserved.

### Daily workflow

Automatic JSON/form login, CSRF, scoped Bearer/Cookie/header credentials, identity verification, expiry refresh, token rotation and bounded re-login. GET/HEAD role expectations with positive resource assertions, permission matrix, session activity, bulk targets, OpenAPI JSON import, request plans, pacing/retries, cancellation, persistent history and baseline comparisons. Export offline HTML/JSON/Markdown/SARIF and reuse project files in CI.

Toolbar actions open an offline user guide and the history folder. Temporary passwords/tokens stay in memory; re-enter them after switching projects or restarting. Projects and history persist in `%USERPROFILE%\.shensec`.

### Verification and boundaries

The Windows build runs the test suite and then verifies both packaged runtimes outside the checkout: real authenticated loopback requests, four roles/eight observations, renewal, SQLite history restart, Qt rendering and all report formats. Build sources and pinned tools are included in the repository. Both binaries contain third-party license notices.

This is a beta configuration/access regression workbench. It does not automate browser JavaScript login, CAPTCHA, MFA or interactive OAuth/PKCE, validate JWT signatures, fuzz or exploit targets. Review configured write requests before execution and assess only authorized systems. See [limitations](https://github.com/shenming1115/ShenSec/blob/v0.5.0b1/docs/limitations.md).
