SHENSEC

自动登录 · 会话续期 · 多角色权限回归

Windows 10/11 x64：直接双击 exe。无需安装 Python、uv，也无需命令行或管理员权限。ZIP 用户先解压全部文件，再打开 ShenSec.exe，保留旁边的 _internal 文件夹。

1. 用本地演示熟悉操作

点击顶部 Try local demo。准备数秒后会打开独立演示窗口：4 个角色 × 2 个接口、两次历史扫描、3 项已修复权限问题、4 次会话续期。选择左侧较早的历史记录可查看修复前的红色权限单元格。点击单元格查看预期和证据。

演示只连接本机 127.0.0.1。关闭演示窗口会停止测试服务并删除临时数据，日常项目保留在主窗口。

2. 创建自己的项目

  1. 点击 + New，命名项目，在 Targets 每行粘贴一个完整接口 URL，或导入清单。
  2. 在 Credentials 设置精确的认证来源（例如 https://staging.example.com），填入临时 Bearer / Cookie；自定义 Header 使用环境变量引用。
  3. 自动登录请打开 Auto login，配置登录 URL、JSON 或表单、字段与变量名，再输入临时账号密码。配置验证 URL 和身份成功断言，例如 /role="admin"。点击 Test sign-in 验证。
  4. 需要续期时配置 refresh URL 和 Token/到期字段。不要把密码或 Token 写进 URL、项目标题或非凭据字段。
  5. 点击 Save project，然后开始审计。结果出现后检查 Targets、Findings、Permission matrix 和 Sessions。

3. 配置多角色权限

在 Roles & access 添加 admin、普通用户、其他用户和匿名身份。每个认证角色配置验证 URL 与身份断言。添加 GET/HEAD 权限用例，选择各角色应该 allow / deny；允许访问还需要响应 Header 或 JSON 断言证明拿到了真实资源。用例 URL 必须存在于 Targets。

匿名以外的角色可以临时输入账号密码、Bearer 或 Cookie。密码和 Token 只留在进程内存；切换项目、Clear session credentials 或关闭应用后需要重新输入。项目配置导出只包含变量名。

4. 接受基线，日常复查

  1. 先检查一次完整扫描的证据和修复建议，再点击 Accept selected run as baseline。
  2. 以后对同一项目再次审计，可按 NEW / REGRESSED / RESOLVED / UNVERIFIED 筛选。认证、目标和请求变化会影响可比性。
  3. 无法复查不等于已修复。失败或部分覆盖需先处理认证与连接问题。
  4. 通过 Export report 导出离线 HTML、JSON、Markdown 或 SARIF。

5. 快捷键与数据

Ctrl+S 保存 · Ctrl+Enter 审计 · Ctrl+L 测试登录 · Ctrl+F 搜索。

默认历史目录：%USERPROFILE%\.shensec\workspace.sqlite3。点击 Open history folder 打开；退出全部 ShenSec 窗口后复制整个目录即可备份。升级只替换程序文件，保留此目录。删除此目录会删除项目和历史。

常见问题

Windows 提示发布者未知：此测试版没有代码签名证书。先确认来自项目官方 Releases 并比对 SHA256SUMS.txt，再按组织策略处理系统提示。

单文件启动要等几秒：首次运行需解包运行库。日常频繁启动可以用 portable ZIP。

启动失败：确认使用 Windows x64，ZIP 已全部解压；检查历史目录中的 startup-error.log。不会把原始异常文本或凭据写入启动日志。

登录失败：检查字段名、来源、身份断言及临时凭据。浏览器 JavaScript 登录、验证码、交互式 OAuth/PKCE 和 MFA 需要先人工登录，再临时粘贴会话。

适用范围：检查已获授权的应用。默认 GET/OPTIONS；显式 POST/PUT/PATCH/DELETE 请求可能修改应用数据，运行前检查请求表。只检测配置与访问回归，不验证 JWT 签名，不执行漏洞利用或模糊测试。

English quick start

Double-click the exe, or extract the complete portable ZIP and open ShenSec.exe. No Python, uv, terminal or admin rights needed. Click Try local demo to open an isolated temporary workspace with four roles, two endpoints and before/after history. Close that window to stop the fixture.

Create a project, paste endpoint URLs, configure scoped credentials or automatic login with positive identity verification, then test login and audit. Add roles and GET/HEAD expectations with success assertions. Review a complete scan before accepting it as a baseline. Re-run to inspect new, regressed, resolved and unverified observations. Export HTML, JSON, Markdown or SARIF for review.

Passwords and tokens stay in memory. Re-enter them after switching projects or restarting. History persists in %USERPROFILE%\.shensec. Use the portable ZIP for faster startup. This beta is unsigned.
